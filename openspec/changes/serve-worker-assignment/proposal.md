# Serve honours a signed worker assignment (OC1b, story 1 of 5)

> **Scope.** This change is story 1 of the five that issue
> [#1313](https://github.com/mrnicholasbcarter-code/verdict-core/issues/1313) was split into
> (operator, 2026-11-24): **`verdict serve` honours a signed worker assignment.** The other four
> are separate issues and have their own changes: #1325 (the executor signs the assignment and
> carries run and node ids; the live smoke passes there), #1326 (the dispatch-origin check), #1327
> (task delivery and the status-matcher fix), #1328 (the default executor switch). None of them
> is built or tasked here.
>
> **Marker used in this change.** A fact that comes from code merged in pull request #1299 (the
> OpenCode worker adapter, commit `b0010c10`) is marked **[#1299]**. Everything else was read from
> `main` at `51c935ae` or comes from the operator's recorded decisions on #1313.

## Why

`verdict orchestrate --executor opencode` cannot complete one request through `verdict serve`.
The live smoke on #1277 (recorded on #1313) showed two refusals, and the research for #1313
(`research/issue-1313.md`) found at least four blockers, each visible only after the one before it
is cleared. All four were reproduced hermetically (in-process, fake transport, temporary home, no
model call):

1. **The escalation keyword scanner refuses the worker.** `_task_text` joins every message,
   including OpenCode's own system prompt and whatever the worker has read, so the scanner reads
   words such as "payment" and answers 503 `critical, never offload` with no upstream call. That
   branch of `route()` returns before the route pin of #1299 is reached. 11 of the 13 smoke
   requests ended this way.
2. **The capability gate has no metadata on the relay path.** `metadata_for_gate` is `None`
   unless metadata was passed explicitly or execution-path authority is required, and serve's
   `_build_intelligence()` does neither. A request with `tools` is then dropped
   `required_unknown: Core metadata store unavailable` for every route. The store exists
   (`~/.verdict/model-metadata.json`); it is withheld, not missing.
3. **The pack cannot hold a worker request.** The cheap-path pack's mandatory slot is the whole
   request text, capped near 16K tokens: 32,000 characters pass, 34,000 are denied "exceed the
   cheap-path context budget". The first OpenCode request is 130,528 characters.
4. **The pack is injected into the request.** An admitted request gets the compiled pack
   prepended as a system message, so a 20,000-character request became a 40,157-character
   envelope. A worker needs its request forwarded verbatim.

Passing metadata is not enough either: no route in the store carries a `streaming` fact (0 of 6965
records), so a request with `stream: true` is dropped `required_unknown` for `streaming` on every
route; and with metadata on, the Top-4 shortlist can starve a route the orchestrator already
admitted (a pin on the 6th of 6 candidates is denied `candidate_pool_not_shortlisted`).

Underneath all four is one gap: today the route is chosen by a request header. **[#1299]** the relay
treats any request with an `X-Verdict-Worker` header as a worker and pins the route named in its
`model` field, so a worker holding the serve token can name any route in the admitted set, and the
pin is applied only after serve has re-classified the request from its text. The orchestrator
already chose the route (its sufficiency floor, `required_capability_tier(node)`, comes from the
node's risk and kind) and holds the dispatch permit. Serve should honour that choice on proof that
it came from the orchestrator, and spend no effort second-guessing it from text.

This advances the mission ([BOD-342 D15](https://linear.app/bodanglin/issue/BOD-342)): every story
Verdict builds with a free worker is work at no paid cost, and the self-build pipeline
([ADR-052](../../../docs/adr/ADR-052-github-issue-to-ready-pr.md)) needs a worker that can run.

## What Changes

- **A signed worker assignment.** A token carrying route id, run id, node id and expiry, signed
  with HMAC-SHA256 by a **separate generated key** (not the serve token). The worker presents it
  as its bearer credential. Serve verifies it with a constant-time compare; a bad, expired or
  missing assignment is denied with no upstream call.
- **A separate signing key.** Generated by `verdict setup --apply --allow host.serve`, stored in
  its own file `~/.config/verdict/worker-assignment.key` (mode 0600), read by serve and by the
  orchestrator when it signs, never placed in any process environment. Missing key: serve fails
  closed. Rotation: remove the file and run setup again. `verdict doctor` reports the key.
- **Assignments are honoured only on the OpenAI relay surfaces** (`POST /v1/chat/completions`,
  `POST /v1/responses`). Every other path refuses them, so a worker never holds a credential for
  `/v1/route`, `/v1/runs`, receipts or guidance.
- **The bare header selects nothing.** **[#1299]** `X-Verdict-Worker` plus the serve token no longer
  pins a route; such a request is denied. `WorkerAssignedRoute` and its relay and admission
  handling are replaced by the verified assignment.
- **A `model` that differs from the signed route is denied**, not ignored.
- **An assigned lane in `IntelligenceService._route`**, reachable only with a verified assignment
  and placed after the `require_authority` raise (so production-profile serve still fails closed).
  The lane skips the keyword scan, text classification, planner, Top-K shortlist and pack
  injection; narrows to the pinned route right after the active and cooling step; then runs every
  per-route hard gate on that route and mints its proof. Nothing is re-admitted.
- **The capability gate gets its metadata on the lane.** `tools` stays required. `streaming` is
  waived for a verified assignment only, and the waiver is recorded in serve's receipts; stream
  evidence is a later story.
- **One profile, one digest, both sides.** Admission and the relay compute the task profile with
  the same helper in the same mode, so a lane-minted proof verifies at the relay.

## Capabilities

### New Capabilities

- `serve-worker-assignment`: signed worker assignment format and verification, assignment key
  lifecycle, the places an assignment is accepted, and the assigned lane's admission contract.

### Modified Capabilities

None canonical. `openspec/specs/` has no `opencode-worker` capability: the requirements this
change supersedes live in the open change `opencode-worker-adapter` (merged in #1299, not yet
archived). The design lists them in "Supersedes"; the build amends that change's text (task 7.2)
so docs describe only what runs.

## Acceptance criteria

From the acceptance list of #1313 and the operator's decisions, for this story:

- A request is routed on an assigned route only with a valid assignment. A forged, expired,
  field-tampered, wrong-key, truncated or missing-key assignment is denied and **no upstream call
  is made**; no route is pinned.
- A request with the serve token and the `X-Verdict-Worker` header but no assignment is denied; no
  route is pinned.
- An assignment presented anywhere except `POST /v1/chat/completions` and `POST /v1/responses` is
  refused.
- A `model` that differs from the signed route is denied.
- With a valid assignment and an admitted pinned route: the route is served, the body is forwarded
  verbatim (no pack, no extra message), and the upstream `model` is the pinned route.
- A body containing "payment" or "credential", a request with `tools` and `stream`, and a 130 KB
  request are all admitted when the pinned route passes its hard gates; the pinned route on the
  6th of 6 candidates is admitted.
- A pinned route that is outside the admitted set, cooled, of unknown health, unmapped, not in the
  inventory, or an `auto/*` route is denied.
- `tools` is enforced from real metadata; `streaming` is waived and the waiver is recorded in the
  receipt.
- Production-profile serve (`require_authority`) still fails closed for a worker request.
- An assigned request that is explicitly protected (`protected: true`, criticality critical) is
  denied before the ladder: serve never lowers a floor.
- Non-worker relay traffic is unchanged.
- The three admission invariants named in `AGENTS.md` (`tests/test_admission.py`) pass
  unchanged; new tests carry the lane's own guarantee (design, "Invariants").
