## Goals / Non-Goals

**INFERRED goals:** Exact-id interactive selection with a narrow, reviewable mutation; health/visibility/transport explained independently; native Claude refusal; completion that remains fast and offline; one shared-file integrator.

**INFERRED non-goals:** No `defaultModel` or default-provider flag in this story. No fallback model, launch allowlist, worker-policy replacement, model inventory rewrite, credential creation, native Anthropic proxy, new certification, live test suite, or new TUI framework. Existing enable/disable/certify are not redefined. Autocomplete is never a trigger for inventory reads, probes, waits, or receipts.

## Decisions

### (a) Prime target, exact identities, and honest scope

**INFERRED:** Target `<resolved operator agent dir>/settings.json`, key `/enabledModels`, mode `interactive`, registry provider `omniroute`. Resolve the operator dir with `prime_settings.default_prime_agent_dir()` (FACT `prime_settings.py:185-191`), then pass that same explicit dir to harness discovery/registry reads. This avoids the different historical `PRIME_HOME`/`PRIME_AGENT_HOME` aliases in `harness_prime.resolve_paths` (FACT `harness_prime.py:105-117`). Show the resolved path and current project override warning. Never mutate per-launch mirrors or project settings. A missing binary, missing registry/settings, malformed document, symlink, or unrecognized effective path is a refusal, not a bootstrap fallback.

**INFERRED:** Use canonical projection `route_id` as the `enabledModels` string: for registry provider `omniroute`, select `cx/gpt-6-sol`, not its human name, not guessed `cx` provider metadata, and not an automatically rewritten `omniroute/cx/gpt-6-sol`. Strip only an explicitly supplied leading `omniroute/` through the sibling canonical-id contract, then validate the remainder by equality against registry ids and projection ids. Preserve case, slashes and literal colons. No wildcards, regex, `auto/*`, short names, aliases by suffix, or thinking-level suffix guessing. Local raw-id evidence and Prime docs support this chosen form; they do not alone prove every release's resolver. The Prime compatibility adapter must support the discovered release's documented exact-id semantics and fixture-test that matching does not expand via model names. If a token ambiguously resolves to another provider/model/name or colon-as-effort form, mark `identity_unsupported` and refuse. Do not guess a repair.

**INFERRED scope policy:** Replace only the current, uniquely bound `omniroute` entries of `enabledModels` with the chosen nonempty exact list, deduplicated in first-selection order. Preserve exact entries uniquely bound to other registry providers, in original relative order, ahead of the new managed list. Preserve unbound exact historical entries as `retained_unknown / not verified`, disclose them in the preview, and state that this is not a full verified allowlist. Existing wildcard or ambiguous entries make scope classification unsafe: refuse apply and ask the owner to resolve them through Prime `/scoped-models`; do not expand, silently remove, or reinterpret them. Removed omniroute ids need not be healthy. Previously selected stale/unsupported omniroute entries can be removed but never re-added as verified. All settings outside this key, all of models.json, every other provider, and every per-model metadata field remain semantically unchanged. No default/fallback field is touched, even when the current default is outside the chosen list; preview warns rather than repairs it.

**INFERRED independent checks:** `PrimeSelectionRow` wraps each projection row with `registry_provider`, `prime_id`, `visible`, `execution`, `reasons`, and `selectable`. Preserve route/provider, health status, checked_at, fresh_until, expires_at, cooldown and identity fields. Display all seven statuses honestly. Build health from the sibling projection before adding picker-specific Prime visibility: do not insert the picker registry result into EvidenceSnapshots.visibility_unavailable and then use that as a substitute health test. Keep the health row and separate Prime overlay/reasons visible together. `visible=true` requires exact membership in `models.json.providers.omniroute.models`; gateway inventory alone never satisfies it. Missing membership says `not visible to Prime` and offers `verdict harness prime sync-models --dry-run` followed by a separate explicit sync where that existing surface is available. FACT: the existing sync action is registered at `registry.py:2153-2162`, but the baseline nested argparse parser at `parsers_harness.py:183-224` does not expose it. U7 exposes that existing action as the separate `sync-models [--dry-run]` subcommand if it is still absent after sibling integration, with explicit confirmation for a write. Re-discover after sync and discard the old preview. No picker path invokes `_sync_visibility_models`/`refresh_omniroute_visibility`.

**INFERRED execution vocabulary:** `compatible_not_launch_confirmed`, `blocked`, or `unknown`; never derive `can_execute=true` from membership or gateway health. Compatibility requires a supported effective OpenAI API (per-model override before provider API), unchanged exact id passthrough, a recognized configured gateway endpoint bound to the evidence source, binary support, and read-only credential-presence readiness. Inspect only presence, never print/execute apiKey shell commands or read auth.json content into output. Unknown credentials, unsupported API, absent endpoint, identity ambiguity, or unknown release support blocks selection. A fresh VERIFIED row plus these checks may be scoped as verified, but UI says `compatible; execution will be re-confirmed`, not `Prime end-to-end tested`. Health freshness alone and compatibility alone are each insufficient.

**INFERRED:** `selectable` requires current `VERIFIED`, `identity=verified`, `fresh_until > now`, no active restriction/cooldown affecting selection, exact visibility, and compatible readiness. Do not impose a hidden coding/tools floor; show `coding_ok` separately. Unverified, stale, failed, unavailable, excluded, inventory-only or unsupported ids cannot be added. `expires_at` is historical success expiry; the earlier `fresh_until` is the apply deadline. Missing timestamps fail closed. Cached rows are never launch permission.

**INFERRED launch meaning:** `enabledModels` controls interactive Alt+M cycling only. New interactive sessions read it; existing sessions may need `/scoped-models` or restart. Project settings and explicit `--models` can override it. Verdict launch mirrors keep the key (FACT above), but Verdict chooses an exact worker model and runs runtime admission/confirmation again immediately before dispatch. This selection neither constrains all future launches nor authorizes one. No hardcoded fallback may bypass Verdict selection. Certification claims remain untouched.

**Alternative rejected:** Pruning `providers.omniroute.models` as a health allowlist destroys visibility and metadata and confuses inventory with proof. Replacing the whole `enabledModels` array without scope classification would discard other providers. Setting defaultModel would change launch semantics not requested here.

### Refresh and the picker state machine

**FACT API:** Current `refresh_for_consumer(snapshot, *, consumer, needed_ids, config, cache, transport=None, clock=None, monotonic=None, sleep=None, explicit=False, on_progress=None, cancel=None, lock_path=None, marker_path=None, job_id=None)` returns `RefreshOutcome` (`verified_refresh.py:1251-1291`). U7 constructs `RowInput`/`RefreshSnapshot` from projection rows with enum status values and explicit capacity defaults; U7 loads evidence and projects again after completion rather than trusting `outcome.verified` as proof.

**INFERRED:** A pure transaction preview does no refresh. The interactive/CLI picker consumer invokes refresh before requesting that pure preview, and again before apply. Use `consumer=picker` for preview and `consumer=selection` for apply, supplying exactly proposed added/retained managed ids, not preserved unrelated entries, removals-only ids, or all 6.7k inventory rows. The no-id picker starts with the bounded current page from the verified-view consumer; chosen ids then become the exact needed list. Fresh ids return reused_fresh without calls or waiting. Involved ids exceeding the coordinator cap remain untested; no uncapped retry loop or second hidden sweep.

**INFERRED sequence:** read-only discovery -> choose exact ids -> bounded prepaid refresh with progress only -> optional disclosed manual metered/unknown plan and separate spend `[y/N]` -> wait -> reload full needed evidence -> evaluate health/visibility/transport -> pure diff -> apply `[y/N]` -> second refresh/reload -> compare config/dependencies and proof -> guarded commit. Automatic refresh does not fabricate manual consent. Use sibling plan/execute and `VerifiedControlsController` for metered/unknown routes. Display selected count, exact ids, request estimate, quota warning, and caps; currency estimate is unavailable. FACT baseline defect/dependency: the manual metered/unknown plan reaches a prepaid-only filter (`model_refresh.py:97-101,366-374`, `verified_refresh.py:354-366,389-402`); the controller assigns that defect to `bod292-u3-fix`. INFERRED fixed contract: depend on that unit-3 fix commit, and record its SHA in the U7 handoff before integration lands. Valid confirmed METERED/UNKNOWN plan ids execute through the sibling bounded plan/execute path without automatic prepaid filtering; an unconfirmed, expired/stale, changed, or otherwise invalid plan refuses before calls. Consent permits the disclosed probe, never fabricates proof. The picker waits, then re-reads evidence for the exact involved ids; execution and plan completion do not imply coding_ok or identity verification. This fixed consented execution is required before the workflow ships; there is no unavailable-backend fallback or prepaid capacity relabelling in the delivered design. U7 does not patch sibling-owned refresh files. A spend refusal leaves current facts unchanged, not verified by consent. If facts change the selected set or diff, discard apply consent, re-preview, and ask again. Cancel/busy/cap/disabled/joined results never promote stale proof. Completed cache proof may persist; settings and backups stay unchanged on cancellation.

**INFERRED:** Keep the UI responsive through a cancel-aware worker and bounded progress events; Esc/Ctrl-C stops future refresh dispatch via the sibling shared cancellation rules. No provisional working list while refresh runs. At apply, re-evaluate freshness with injected current time under the settings lock immediately before replacement; equal fresh_until is expired. Runtime confirmation remains independent later.

### (b) Prime transaction module API and safety

**INFERRED:** New `verdict/harness_prime_selection.py` owns immutable documents/plans and guarded file I/O; new `verdict/harness_prime_compat.py` owns read-only exact-binding checks. APIs below are interface notation, not executable Python:

```text
SettingsDocument(path, raw_bytes, value, pre_digest, file_identity)
PrimeDependencies(registry_digest, project_digest, discovery, compatible_rows)
SelectionPreview(schema, target, policy, selected_ids, before, after,
                 added, removed, retained, refusals, pre_digest,
                 dependency_digests, plan_digest, proof_deadline)
preview_selection(settings: SettingsDocument, projection_rows,
                  *, selected_ids, dependencies, now) -> SelectionPreview
apply_selection(preview, *, expected_pre_digest, confirmed=False,
                paths, reload_rows, reload_dependencies, clock) -> SelectionResult
preview_restore(settings: SettingsDocument, receipt, *, backup_bytes)
                -> RestorePreview
restore_selection(preview, *, expected_post_digest, confirmed=False,
                  paths, clock) -> RestoreResult
```

**INFERRED:** Pure previews consume supplied settings, projection and dependencies with a timezone-aware `now`; apply/restore take an injected aware `clock` callable for repeated boundary checks. They perform no clock/disk/network reads, locks, directory creation, backups, transports, probes, admission, or writes. The loader reads a regular owner-controlled JSON-object settings file, rejects duplicate keys/type errors, and records SHA256 of the exact bytes, not only parsed JSON. Existence/path/file identity and raw registry/project digests bind dependencies without printing documents. No secret-bearing full-document diffs. Display only `/enabledModels` before/after, exact additions/removals/retained warnings, path, policy, proof deadline and digests. Plan digest binds selected ids, key diff, file identity/dependencies and deadline. `proof_deadline` is the minimum selected fresh_until at preview; if it has elapsed, even a successful apply-time refresh requires a new preview/digest and new confirmation, never a silent extension of the approved plan. Digest guards accidental change; it is not authentication.

**INFERRED apply contract:** `confirmed is True` and `expected_pre_digest == preview.pre_digest` are mandatory; empty/no-op selection still validates current proof and dependencies. Refresh and spend decisions finish before the settings lock, never while holding it. Acquire a nonblocking cross-process `fcntl.flock(LOCK_EX|LOCK_NB)` on `<agent_dir>/.verdict-prime-selection.lock` (0600, reject symlinks). A held lock returns `busy` without backup/config mutation; the lock file may exist as bookkeeping. Under the lock, re-read settings/registry/project/binary compatibility and reload current projection rows from local evidence only (no live reads, refresh or wait inside the lock); refuse any config/dependency/diff mismatch, absent Prime, expired proof, or new blocker. Do not silently merge a changed file or apply a narrowed selection with old consent.

**INFERRED write order:** If bytes already represent the same scoped array and all validations pass, return `unchanged`: no settings write or backup. Otherwise write an immediate byte-for-byte backup of the currently locked settings before replacing it. Use `settings.json.verdict-select-<UTC YYYYMMDDTHHMMSSffffffZ>-<transaction-id>.bak`, exclusive create, 0600; transaction id is random nonsecret. Preserve unrelated JSON values and key order; serialize only the approved key change (whitespace normalization is disclosed, no other semantic edits). A unique same-directory temporary file is exclusive-created 0600, fully written/fchmod/fsync, then settings digest and inode are rechecked immediately before atomic `os.replace`; fsync the directory. Recheck proof deadline immediately before replacement. Settings becomes 0600. Abort on any recheck mismatch; remove temporary artifacts, keep the untouched config and valid recovery backup. Never use a shared fixed `.tmp` name.

**INFERRED receipt:** A private `settings.json.verdict-select-<stamp>-<transaction-id>.receipt.json` binds target, schema `verdict.prime-selection-receipt/v1`, transaction id, pre/post byte digests, backup digest/name, timestamp, exact scoped before/after and status. No raw settings, credentials or provider docs. Prepare/fsync the receipt before replacement with `prepared` status; mark `applied` atomically after replacement. After a crash, current digest matching pre means not applied; matching post plus intact backup allows explicit restore; any other digest refuses. Failure after a durable settings replacement must return `applied_receipt_incomplete` with recovery instructions, not falsely claim no write or automatically overwrite later edits.

**INFERRED retention:** Keep the newest five completed selection backup/receipt pairs by stamp/id, prune only exact transaction-owned names after successful receipt finalization under the same lock. Keep the current transaction, prepared/incomplete recovery records and unmatched files; never prune enable backups, models.json sync backups, or owner files. No backup pruning on preview, cancel, refusal or idempotent apply. Full private backups may contain secrets: never render/log their contents. Shared `_atomic_write_json`/old disable do not satisfy this API and remain unchanged.

**INFERRED restore:** Pick the latest completed/recoverable selection receipt by default or an explicitly named transaction. Validate owner/path/schema and backup digest without traversing arbitrary paths. Pure restore preview shows only the scoped key reversal and whether full preimage restore is safe. Restore requires affirmative y/N, `expected_post_digest` from the applied receipt, and current byte digest exactly equal to that post digest both under lock and just before replacement. Any later edit, even unrelated or whitespace-only, refuses with `config_changed`; no force mode. Preserve the selected backup/receipt, take a separate private immediate pre-restore backup using `settings.json.verdict-restore-<stamp>-<transaction-id>.bak`, then atomic byte-for-byte restore of the validated preimage at 0600. Record restore result privately. Prune only restore-owned completed pairs to five. Restoring historic configuration is explicitly `restored prior scope, not newly verified`; it never claims old ids still work. Repeating a recorded restore when current digest equals recorded restored digest is `unchanged`; otherwise never overwrite. Restore is unavailable if Prime/discovery or backup identity is unsafe, but does not require historical restored ids to be freshly healthy because it is recovery, not verified selection.

**INFERRED concurrency boundary:** All selection/restore writers cooperate on this lock. Digest/file checks catch owner edits between preview and apply and during preparation. A non-cooperating writer can still race in the tiny check-to-replace interval; ordinary files have no portable compare-and-swap. Document that limit and advise against concurrent settings editors. Never claim this advisory lock prevents arbitrary external writes. Unsupported locking platforms fail closed rather than skip locking.

**Alternatives rejected:** Canonical-JSON digest hides owner byte edits; a whole-document print leaks secrets; old fixed backup names lose immediate preimages; automatic merge/force restore can overwrite later owner intent.

### (e) Pure completion API and frozen local source

**INFERRED:** The core receives immutable snapshots and injected time; it has no file/network/clock/probe/refresh/admission/registry dependency. **INFERRED source:** U7 owns `verdict/tui_completion_snapshot.py`. ## Risks / Trade-offs

- [Raw Prime patterns can match model names or another provider] -> Exact-id resolution fixture and supported-release binding; refuse ambiguity, never guess or claim static visibility proves launch.
- [Global interactive scope does not govern workers/project overrides] -> Warn explicitly, preserve runtime admission and launch selection, offer no default/fallback edits.
- [Advisory lock cannot control arbitrary external writers] -> Pre/post dependency checks, immediate private backup, refusal on observed changes, documented small check-to-replace race.
- [Proof expires during confirmation/preparation] -> Second consumer refresh, reload, lock-time and final-replace fresh_until checks; refuse rather than silently change the preview.
- [Preview refresh itself spends prepaid quota] -> Explain it before picker work; respect sibling disable/caps and separate metered consent; no completion probing.
- [Private backups can contain secrets] -> 0600/owner-only bookkeeping, bounded owned retention, no content logging, path/schema/ownership checks.
- [Snapshot labels become stale] -> Recompute age labels locally, never apply snapshot authority, explicit command reload only.
- [Claude report is useful but cannot satisfy native selection] -> Honest `unsupported / NEEDS_OWNER` BOD-102 block, no apply, no changed certification.
