# Design

## Context

Waves 5-7 of V1 hardening: S09 (BOD-437), S10 (BOD-438), S11 (BOD-414), S05 phase 2 (BOD-297), and the S03-C executor-origin addendum (BOD-433). Waves 2-4 are in `openspec/changes/v1-authority-inventory` and `openspec/changes/v1-permits-streams-public-models`. All results are recorded on the combined integration branch `integration/v1-waves5-7`.

## Decisions

1. **Terminal vs checker rows (S09)**: a `terminal` row is written once per model attempt directly from the dispatch/relay/autodev path and never carries `quality_credit`. A `checker_result` row is written only when an *independent* verification event occurred (the runtime's own `verify` event for orchestration, never the attempt's own success signal), and only it may carry `quality_credit` (0, 0.5, or 1, matching the checker's own outcome class). Operational failure classes (quota/auth/timeout/stream_drop/5xx/cooldown/tool/other) can never carry credit. This separation is what lets S10 trust history: an attempt row alone proves nothing about quality, only a joined checker row does.
2. **Crash-safety, not crash-atomicity (S09)**: the ledger writer takes a `flock`, loops `os.write` until every byte is written, then `fsync`s. A process killed mid-write can still leave a torn row; S09/S10's join logic (`load_checked_attempts`) rejects a torn or tampered row rather than the writer preventing it, because file-level atomic replace is not available for an append-only, multi-writer, growing ledger without rewriting the whole file per append.
3. **Checker-join joins on verified semantics, not on trust in the writer (S09)**: a row joins to a run only when all hold: the receipt verifies; the digest is equal; the key exists in the run; the row is byte-equal to the recomputed row; the verified check time (from the runtime's events, never the ledger row's own `ts`) is at or before `as_of`; it is the first row for that key. Every other case is rejected with a named reason (`checker_digest_mismatch`, `scope_mismatch`, `tampered`, `future`, `duplicate`) so later S10 disclosure counts are meaningful.
4. **Order-only demotion, never a rank cliff (S10)**: `score_task_history` returns a Beta-smoothed score (`(weighted_accepted + 0.5*weighted_partial + 1) / (weighted_eligible + 2)`, 0.5 prior with no qualifying data) with a 30-day window and 7-day half-life weight `2 ** (-age_days / 7)`. A route scoring below 0.4 with at least 3 *unique* verified observations is marked `demoted`; demotion only changes tie-break order among an already-admitted shortlist (`(demoted, -score, route_id)`), and never removes a member or changes membership. This keeps verified history advisory, consistent with ADR-0001's hard-eligibility-first invariant.
5. **No unverified scoring path (S10)**: the prior unverified classification/raw-accept-rate fallback in `candidate_pool.py` is deleted outright (`RouteEvidence.task_success_rate` had no production writer after the change). Once any matched observation carries an independently verified `quality_credit`/`observed_at` (from S09's join), `score_task_history` runs; unverified/raw matched rows contribute nothing. A loader exception fails closed to "no history" (order-only demotion skipped), never to blocking admission.
6. **Bounded disclosure, no raw paths (S10)**: `intelligence.py`'s `history_disclosure` field on the candidate-pool receipt carries only counts and a fixed reason-code vocabulary (`status`, `reason`, `error_class`, `observations_count`, `omitted`, `reasons: dict[reason_code, count]`). Raw omission strings (which can embed absolute local filesystem paths) and exception messages are logged locally only, never placed in a receipt that API callers can read. This followed two Codex Luna review rounds that found progressively narrower leaks (a raw-rate scoring path, then a `contextlib.suppress` swallowing failures, then the omission-string/exception-message leak).
7. **Doctor provenance fails closed on an unrecorded build (S11)**: `installed_runtime_rows` marks a unit FAILED whenever its recorded build is unknown, even if the path looks right — "at the reviewed path" is not proof of "the reviewed build". A build is recorded via dist-info `direct_url.json`, then a `verdict-build.json` stamp the installer writes, then a file-read of git HEAD (never the `git` binary). The gateway origin shown in a doctor row is reduced to `scheme://host:port` plus a path marker only; query strings and userinfo (which can carry tokens) are dropped, because the shared `provider_bootstrap.redact_url` only masks userinfo.
8. **Install plan and rollback precede any service mutation (S11)**: every installer (prove-at-rest, acceptance, census) now returns a `plan` (create/replace/keep, or remove/absent for uninstall) and a `rollback` path; `save_rollback` copies every unit file that will be replaced or removed into `$VERDICT_HOME/service-rollback/<UTC>/` *before* any write. A dry run returns the plan and mutates nothing. This gives the operator a path back without requiring a second system-level backup mechanism.
9. **Maintenance producers share one coordinator, each with its own budget (BOD-297 phase 2)**: census keeps its small per-cycle maintenance size (4 routes / 16 requests / 2-per-provider); prove-at-rest's chat phase does not inherit that size (it would starve the fresh-passport set the live daemon needs every 300s). Instead it computes its own bounded config from the *daemon's own flags*: `max_routes = max(1, min(daemon_max_requests // 2, HARD_MAX_ROUTES=50))`, `max_requests = min(daemon_max_requests, HARD_MAX_REQUESTS=100)`, `wall_seconds = min(daemon_max_wall_seconds, HARD_MAX_WALL_SECONDS_MAINTENANCE=600)`. Both producers go through the *same* flock, marker, bucket and `auth_gate` machinery; only the numeric budget differs per caller.
10. **No partial-probe spend (BOD-297 phase 2)**: the coordinator reserves a whole probe's token/request cost before dispatching any part of it. A budget too small for one full probe makes zero calls, where the old per-route loop could spend the chat half before its own cap fired. This is a deliberate behaviour change from "partial spend allowed" to "whole-probe-or-nothing", traded for simpler, provably-bounded budgets.
11. **`auth_gate` reports the real stop reason, not a confirmed outage it never checked (BOD-297 phase 2)**: `auth_gate` returns a 3-state result — confirmed outage (`True`), a genuine per-route failure (`False`), or unconfirmed (`None`, when the gate itself cannot afford its own confirmation call against the coordinator's *live* remaining budget, `config.max_requests - requests_made`, not the caller's own un-updated `stats.requests`). The `None` case stops the job with the real `wall_cap`/`request_cap` reason and never claims an outage nobody actually checked. This took three review/repro rounds (items 18, 19 in `bod297-parent-decisions.md`) to land because the budget accounting is shared between the gate's own confirmation call and the coordinator's job-level cap.
12. **Provider stop is a route-level outcome, never a job-level cap (BOD-297 phase 2)**: when every candidate in a job was either probed or skipped by a provider/route stop, the job's own reason is "complete", not "bucket" or "capped". Only a real bucket denial sets `REASON_BUCKET`. This was a pre-existing coordinator labeling bug exposed by the maintenance cutover, fixed once in the coordinator for every caller rather than patched per-producer.
13. **The offline majority-pool auth-outage heuristic is deleted, not ported (BOD-297 phase 2)**: both production callers of prove-at-rest always build the live daemon with `gateway_auth_check` set, so the heuristic (`auth_outage_consecutive`/`auth_outage_distinct_pools`/`_auth_fail_pools`, buffer-then-flush) only ever ran with injected offline test transports and had become unreachable in production once the coordinator's own provider-stop (decision 12) fired after the first failure. It is deleted for the chat phase; the agentic phase (U6, untouched by this change) keeps its own separate heuristic and buffer.
14. **Executor-reported gateway origin is attested, not the normalized dispatch target (S03-C)**: `normalize_gateway_origin` reduces a URL to `scheme://lower-case-host:explicit-port`, dropping path/query/fragment, wrapping `urlsplit` itself in `try/except` so a malformed URL (e.g. an unbalanced IPv6 literal) normalizes to `None` rather than raising. `executor_gateway_origin` returns the executor's raw reported origin unchanged (or `None` if it reports nothing); `gateway_origin_matches` normalizes both sides before comparing. `runtime.py` denies with `dispatch_denied: executor origin mismatch` only when the executor *reports* an origin and it does not match the bound scope; `None` is accepted (U1). No permit is committed and the executor is never called on a mismatch; there is no reselect or retry for this failure.

## Risks / Trade-offs

- S05-C (`admit_prove_confirm` confirm loop onto the coordinator), S05-D (concurrency lanes, crash accounting, renewal slots, a coordinator-owned durable cursor) and the agentic-phase coordinator lease (U6) remain deferred; `output_tokens` and `cooldown_seconds` stay validated-but-unused config knobs.
- `DagRuntime` still runs without the executor-origin check wired through `RuntimePolicy.require_dispatch_permit` defaulting off in production (`verdict/orchestration/run.py`); S03-C's new check lives at the same dispatch seam but the flag that would make permits mandatory there is still off.
- Per-attempt checker results from a run-level reviewer, and a checked-partial (0.5) *producer*, do not exist yet; only a 0/1 checker is wired, so `score_task_history`'s partial-credit path is exercised only by tests, not by any current producer.
- `test_run_controls.py::test_prime_headless_executor_kills_subprocess_on_cancel` is a known pre-existing host-timing flake under combined vgate load (confirmed stable in isolation across repeated runs on S10 and S09 heads), unrelated to any file this change touches; it is not fixed here.
- No live acceptance run against the operator's real gateway is claimed by this change; it is pre-merge implementation and automated-test verification only, consistent with the umbrella plan's Not Claimed notice.
