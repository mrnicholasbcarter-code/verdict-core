# Spec Delta — admit-snapshot-keeper

## Purpose

Introduce the admission snapshot keeper: a 5-minute background timer that keeps
`~/.verdict/admit-last-good.json` and the catalog cache fresh without model calls,
so `verdict serve` can always load a valid admission snapshot at startup even when
the OmniRoute gateway is temporarily unreachable.

## ADDED Requirements

### Requirement: Admission snapshot keeper command

The system MUST expose a `verdict admission refresh` command that:

- Calls `load_omniroute_admit_snapshot` with `catalog_scope="full"` and
  `aggregate_deadline_seconds=120.0`.
- Makes NO calls to any inference, chat, completions, responses, or messages
  endpoint.
- Exits 0 when `snapshot.stale_served == ()` and `snapshot.catalog` and
  `snapshot.connections` are both non-empty.
- Exits non-zero (keeping the existing last-good file intact) when the fetch
  fails or any surface is stale.

#### Scenario: Successful refresh writes last-good file atomically

- **WHEN** `verdict admission refresh` is invoked AND OmniRoute is reachable
- **THEN** `~/.verdict/admit-last-good.json` exists AND is a valid JSON file AND
  is 0600 AND `verdict admission refresh` exits 0

#### Scenario: Failed fetch keeps existing last-good intact

- **WHEN** `verdict admission refresh` is invoked AND all non-catalog OmniRoute
  surfaces time out AND a valid last-good file exists
- **THEN** the existing last-good file is unchanged AND `verdict admission refresh`
  exits non-zero (stale_served non-empty)

#### Scenario: No inference endpoint is ever called

- **WHEN** `verdict admission refresh` is invoked with any network outcome
- **THEN** no request is made to any path matching `/v1/chat/completions`,
  `/chat/completions`, `/v1/completions`, `/completions`, `/v1/responses`,
  `/responses`, `/v1/messages`, or `/messages`

### Requirement: Admission snapshot keeper timer

The system MUST provide a systemd user timer `verdict-admit-snapshot.timer` that:

- Runs `verdict admission refresh` with `OnUnitInactiveSec=300` and
  `OnStartupSec=60` (no `OnCalendar`, no `Persistent=true`).
- Is installed by `verdict setup --apply --allow host.admit-snapshot-timer`.
- Is removed by `verdict admission refresh --uninstall`.

#### Scenario: Timer unit uses OnUnitInactiveSec and not OnCalendar

- **WHEN** the timer unit file is generated by `verdict setup`
- **THEN** the unit file contains `OnUnitInactiveSec=300` AND `OnStartupSec=60`
  AND does NOT contain `OnCalendar` AND does NOT contain `Persistent=`

#### Scenario: Timer is installed by setup and removed by uninstall

- **WHEN** `verdict setup --apply --allow host.admit-snapshot-timer` is run
- **THEN** `verdict-admit-snapshot.timer` and `verdict-admit-snapshot.service`
  are present in the systemd user unit directory

### Requirement: Doctor freshness rows

`verdict doctor` MUST include:

- An **Admit-snapshot keeper timer** row: `"ok"` when active with a successful
  last result; `"failed"` (→ `"not-configured"` pre-setup) otherwise.
- An **Admit-last-good freshness** row: `"ok"` when the file exists and its
  newest surface is younger than `ADMIT_LAST_GOOD_MAX_AGE_SECONDS` (15 min);
  `"warning"` with a named repair command when missing or stale.

#### Scenario: Doctor shows ok when timer is active and last-good is fresh

- **WHEN** `verdict-admit-snapshot.timer` is active AND
  `~/.verdict/admit-last-good.json` was written less than 15 minutes ago
- **THEN** `verdict doctor` reports both the Admit-snapshot keeper timer row
  and the Admit-last-good freshness row with `"ok"` status

#### Scenario: Doctor shows warning when last-good is stale

- **WHEN** `~/.verdict/admit-last-good.json` exists AND its newest
  `fetched_at` timestamp is older than `ADMIT_LAST_GOOD_MAX_AGE_SECONDS`
- **THEN** `verdict doctor` reports the Admit-last-good freshness row with
  `"warning"` status AND includes a named repair command in the detail
