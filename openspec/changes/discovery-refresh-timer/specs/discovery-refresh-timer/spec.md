# Spec Delta — discovery-refresh-timer

## Purpose

Introduce the discovery registry refresh timer: a 6-hour background timer that
keeps `$VERDICT_HOME/discovery/registry.json` within its 12-hour TTL by probing
only FREE-capacity routes, with no paid or subscription model calls.

## ADDED Requirements

### Requirement: discovery refresh --free-only flag

The `verdict discovery refresh` command MUST accept a `--free-only` flag that:

- Restricts the probe to routes with `capacity_class == "free"` only.
- Makes no paid or subscription model calls when `--free-only` is set.
- Writes a registry containing only free-capacity entries.

#### Scenario: free-only filters out subscription routes

- **WHEN** `verdict discovery refresh --free-only` is invoked AND the catalog
  contains both FREE and SUBSCRIPTION routes
- **THEN** only FREE routes are passed to `run_refresh` AND no SUBSCRIPTION route
  is probed

### Requirement: Discovery registry refresh timer

The system MUST provide a systemd user timer `verdict-discovery-refresh.timer`
that:

- Runs `verdict discovery refresh --free-only --force --wall-budget 300` with
  `OnUnitInactiveSec=21600` (6 h = `REGISTRY_TTL_S // 2`) and
  `OnStartupSec=120`.
- Uses no `OnCalendar` and no `Persistent=true`.
- Is installed by `verdict setup --apply --allow host.discovery-refresh-timer`.

#### Scenario: Timer unit uses OnUnitInactiveSec and not OnCalendar

- **WHEN** the timer unit file is generated by `verdict setup`
- **THEN** the unit contains `OnUnitInactiveSec=21600` AND `OnStartupSec=120`
  AND does NOT contain `OnCalendar` AND does NOT contain `Persistent=`

#### Scenario: Timer interval keeps entries inside TTL

- **WHEN** `INTERVAL_S` is defined in `discovery_refresh_service`
- **THEN** `INTERVAL_S < REGISTRY_TTL_S`

#### Scenario: Service uses --free-only and --force

- **WHEN** the service unit file is generated
- **THEN** the `ExecStart` line contains `--free-only` AND `--force` AND does
  not contain any inference endpoint path

### Requirement: Discovery registry refresh setup and doctor integration

The system MUST expose the discovery refresh timer through `verdict setup` and
`verdict doctor`:

- `verdict setup --apply --allow host.discovery-refresh-timer` installs the
  units idempotently, creating the unit directory when absent.
- `verdict doctor` includes a "Discovery registry refresh timer" row (`ok` when
  the timer is active; `failed` with a repair command otherwise).
- `verdict doctor` includes a "Discovery registry freshness" row (`ok` when
  `registry.json` exists and its `written_at` is within `REGISTRY_FRESHNESS_WARN_S`;
  `warning` when missing, unreadable, or stale).

#### Scenario: Setup installs timer and doctor shows ok rows

- **WHEN** `verdict setup --apply --allow host.discovery-refresh-timer` is invoked
  AND the unit directory does not yet exist
- **THEN** `verdict-discovery-refresh.service` and `verdict-discovery-refresh.timer`
  are written AND `verdict doctor` includes rows labelled
  "Discovery registry refresh timer" and "Discovery registry freshness"
