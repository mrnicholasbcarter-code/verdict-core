# Pipeline lessons (builders read this before starting and again before the first review)

Recurring defects found by review in this repository. Each has the PRs where it was seen. Advisory only: it never replaces a gate, a test or the review. Kept to 15 entries; the retro step proposes an entry only after the same kind of defect appears in two stories, and proposes retiring one that has not recurred in ten runs. This file is versioned: a lesson changes only through a pull request.

1. **A new test must be able to fail.** Revert the fix and watch it fail. Seen: an `or True` assertion, a guard that skipped every assertion, a test that passed `env` and so never reached the code path, a positive test that passed when nothing loaded. (#1297, #1298, #1299, #1358, #1361)
2. **Docs describe only what runs.** Proposal, design, tasks, spec delta and code must agree before the push; remove text for anything descoped, and remove task or review notes that still say a check is "expected to fail" once the code under it has landed. A doc guarantee must not claim more than the code verifies: a spec scenario that joins two phases (for example cancel before dispatch, and cancel during terminal bookkeeping) must be split by phase, each with an outcome the code can deliver. (#1298, #1299, #1303, #1307, #1329, #1339, #1361)
3. **Tick a task only with evidence; `(post-merge)` is only for live checks on merged main.** Never tick a live check "by design", never park build work as post-merge. (#1298, #1299)
4. **Missing data is `null` with a reason field.** Not 0, not an empty object, not a string such as "undefined". (#1298)
5. **Never guess an external interface.** Check the endpoint, flag, field name or config key against the installed tool or its docs first. (#1298 gateway endpoint, #1299 OpenCode permission format)
6. **Bad input on a guarded path fails closed.** Missing, empty, null and wrong-type values each need a test showing no upstream call was made; validate nested shape the way the real loader does, and reject contradictory values such as `status: pass` with a non-zero exit code. A well-formed but out-of-range value (for example an `exp` too large to convert to a timestamp) must map to the specified refusal, not an uncaught exception. Parse ambiguous input (for example a filename containing spaces or ` - `) against the known owned values, or reject it, never take the first plausible reading. (#1299, issue #1307 unpushed branch, #1329, #1358)
7. **Clean up on every exit path, not only on errors.** Process groups, temp dirs, thread-local state: normal exit, timeout, cancel and exception. Nested use must restore the outer state. A helper thread that outlives its timeout must be bounded (cap the outstanding helpers, treat a failed thread start as the specified refusal). Shutdown is an exit path too: test close-before-cancel as well as cancel-before-close, an exception thrown into a lifespan, and late work that finishes after teardown; cleanup must still run, off the event loop, and a closed queue must refuse new work explicitly. (#1297, #1299, #1350, #1361)
8. **Record real reasons, and classify a failure by its real origin.** An exclusion or failure reason must come from the check that rejected the item, never a default or a success reason. A failure class (environment versus implementation) must come from evidence of the cause: an unresolved import the change itself introduced is not an environment fault, and a missing gate executable is not an implementation failure; test both directions. (#1305, #1339, #1358, #1364)
9. **Timestamps carry an offset and are compared like with like.** Reject naive values; don't parse a tool's human-readable local time. (#1302)
10. **A read-only command must not modify what it reads.** Check the defaults of helpers you call (for example verification that repairs by default). (#1298)
11. **Secrets never reach logs, errors, events or receipts.** Redact before recording subprocess output; test by echoing the secret. (#1299)
12. **Don't loosen a guard to reach one case.** Narrow the exception to the case the issue names and keep the original test. (#1303)
13. **No cache keyed on raw sensitive text at module scope, and no cache without its key.** Scope it to the call; key it on everything that selects the value. (#1297)
14. **Tests run in a temp home.** Nothing may write the operator's real `~/.verdict`. (#1306)
15. **A compatibility exception must be scoped to the callers that need it.** A loader or guard flag that lets old data through (for example for resume or history readers) must be an explicit option those callers pass; fresh input keeps the strict path, and a test shows a fresh input is still refused. (issue #1307 unpushed branch, #1358)
