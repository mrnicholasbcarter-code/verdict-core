# Verdict — Project Constitution (Hermes)

This file is the durable operating constitution for Hermes sessions working inside the
Verdict repository (`verdict-core`). It is stable project policy — it must NOT hold
transient issue/PR/branch/task/blocker state. That state lives in checkpoints and
authoritative external systems (Linear, GitHub, git).

## Architecture (authority ordering)

1. Prime Agent is the durable supervisor of the Verdict autonomous workflow.
2. `/verdict-resume` is the canonical recovery path for every fresh or resumed context.
   Resume/hydrate before dispatching any work.
3. Checkpoints preserve semantic state, not conversation transcripts.
4. Fresh bounded subagents are preferred over long-lived worker context.
5. Linear is the planning authority (project/team scope, objective, ACs, priority, relations).
6. GitHub PR/CI/merge state is the integration authority (exact head, checks, merge).
7. git/worktrees are the execution authority (source of truth for local state and ownership).
8. Authoritative external state overrides remembered/cached state.
9. Never infer current execution state solely from conversation history.

## Operating rules

- Run the five Verdict Core skills (installed from this repo's own `.agents/skills`/
  `.prime/agent/skills`/`.claude/skills` mirrors — they are canonical; do not replace
  with similarly named external skills):
  - `verdict-resume` — canonical recovery path. Run it first in every session.
  - `hydrate-context` — build the version-1 packet before creating/resuming an attempt.
  - `verdict-dispatch` — dispatch a bounded worker with an explicit target and lease.
  - `verdict-proof` — verify worker evidence; parent-run verification is authoritative.
  - `verdict-finish` — review, PR/CI, merge, durable closeout.
- Resume/hydrate before dispatching: never dispatch work from an unhydrated context.
- Checkpoints are written through `scripts/prime_workflow.py write_checkpoint`
  (validated field list, no state regression, carries `completed_issues`).
- Prefer the project's existing mechanisms (`scripts/prime_workflow.py`,
  `scripts/prime_supervisor.py`, `scripts/prime_state.py`) over new parallel systems.
- Keep MEMORY.md tiny. It holds durable operational lessons only — never live workflow
  state (issue numbers, PR numbers, branches, commits, blockers, CI status, leases,
  ownership, current task progress).
- External truth (Linear, GitHub, git/worktrees) outranks any checkpoint or memory claim.
  Checkpoint values that can change externally are claims to verify, not facts.
- Bounded subagents receive only their task contract and required context; their
  conversation history is never a hidden dependency for future recovery.
- Spec Kit integration: the repo no longer tracks a stale `.specify/feature.json`
  pointer. Prefer project Spec Kit scripts when present; otherwise use the host's
  installed Spec Kit / `spec-driven-development` skill templates (see
  `docs/guides/prime-workflow.md`).
- Durable state layout: `$(git rev-parse --git-common-dir)/verdict-prime/` — checkpoint,
  leases, issues/packets/receipts/proofs/evidence, sessions, run/outcome/supervisor JSON.
