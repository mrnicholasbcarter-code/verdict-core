# Identify maintenance

`verdict identify install-service --dry-run` previews the replacement user units. `verdict identify install-service` installs them; `verdict identify uninstall-service` removes them. `verdict setup` offers the same installer after explicit confirmation. Installation never enables the retired prove-at-rest or census units; keep those disabled.

Defaults are defined together in `verdict/identify_service.py`: passive every **3 hours**; a separate screen every **6 hours**, using `--capacity free,subscription --max-per-provider 16 --max-routes 40`. Each run probes at most 40 stale free and subscription routes (shared) and at most 16 per provider, in task-rating order, within the screen's built-in 600-second wall budget. Routes not reached are reported as `skipped_cap` or `skipped_deadline` and remain for the next run; the 30-minute systemd timeout is only a backstop. A screen uses the existing consented missing-proof flow and skips fresh proof. Enabling unchanged units does not manually trigger a screen.

The passive service runs `verdict identify --passive --json --save-report --refresh-health-cache`. The save flag atomically writes `$VERDICT_HOME/identify-latest.json` (default `~/.verdict/identify-latest.json`) with mode 0600. The refresh flag folds OmniRoute's observed traffic (the health matrix, plus signed webhook events when registered) into the health cache as chat-only liveness; it never grants tool or agentic proof. Without either flag passive identify remains read-only. It always makes zero model calls and no gateway writes. JSON is also retained in the service journal.

Check `verdict doctor`, `systemctl --user status verdict-identify.timer verdict-identify-screen.timer`, and `journalctl --user -u verdict-identify.service -u verdict-identify-screen.service`. Doctor checks both timers and the passive report: missing, future, six-hour-old, or source-error reports are red. Installed-runtime rows show the package/build and state scope. Timer rows show last attempt, completion, result and next run; unknown values remain explicit. Health-cache evidence still must contain a fresh or usable stale route. This does not relax the eligible-free-route requirement in hourly acceptance.

These are installation and diagnostic interfaces, not a claim of real-host acceptance. The parent must install merged main and verify the units and report after freshness before declaring the story Done.
